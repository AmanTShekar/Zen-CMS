# Installation & Deployment Runbook

This runbook covers two scenarios: (1) cloning the monorepo for active development, and (2) scaffolding a new standalone project using the CLI.

---

## Option A: Scaffold a New Project (Recommended for Users)

Use `create-zenithcms-app` to bootstrap a new standalone Zenith CMS project in under 60 seconds.

### Prerequisites
- **Node.js**: v20.11.0 or later (LTS)
- **Package Manager**: `npm`, `pnpm`, or `yarn`
- **Database**: A running MongoDB or PostgreSQL instance

### 1. Run the Scaffolding CLI

```bash
npx create-zenithcms-app my-project
```

The interactive CLI will prompt you for:

| Prompt | Default | Description |
|---|---|---|
| Project directory name | `my-zenith-cms` | The folder that will be created |
| Database adapter | `MongoDB` | Choose `1` for MongoDB or `2` for PostgreSQL |
| Database connection string | `mongodb://localhost:27017/zenith` | Your actual database URI |
| Choose template | `1` | Choose (1) Blank, (2) Blog, or (3) E-Commerce |

> [!TIP]
> Run with `--yes` to skip all prompts and use defaults: `npx create-zenithcms-app my-project --yes`
>
> Run with `--database postgres` to pre-select PostgreSQL: `npx create-zenithcms-app my-project -d postgres`

### 2. Install Dependencies (if not done automatically)

```bash
cd my-project
pnpm install
```

### 3. Configure Environment

The CLI generates a `.env` file pre-populated with your inputs. Verify it before starting:

```bash
# .env (auto-generated by CLI)

PORT=3000
JWT_SECRET=<auto-generated>
COOKIE_SECRET=<auto-generated>

DATABASE_URL=mongodb://localhost:27017/zenith
DATABASE_TYPE=mongodb
```

### 5. Start the Server

```bash
npm run dev
```

The CLI will automatically launch your default browser to `http://localhost:3000/admin`!

### 6. Log into the Admin UI

When the Admin UI opens for the first time, you will be greeted by the **Setup Wizard**. Follow the interactive, beautiful UI to securely provision your initial Super Admin account!

## Option B: Monorepo Development (For Contributors)

This covers initializing the full Zenith CMS monorepo on a local development environment.

### 1. Prerequisites

Ensure the target environment meets the following specifications:

- **OS**: macOS, Linux, or Windows (WSL2 recommended)
- **Node.js**: Minimum `v20.11.0` (LTS)
- **Package Manager**: `pnpm` (Minimum `v9.15.0`)
- **Database**:
  - PostgreSQL 15+ (if using the Relational Adapter)
  - MongoDB 6.0+ (if using the Document Adapter)

### 2. Clone the Repository

```bash
git clone https://github.com/AmanTShekar/Zenith-CMS.git
cd Zenith-CMS
```

### 3. Configure Environment

```bash
cp .env.example .env
```

Modify `.env` to point to your local database. Set `INITIAL_ADMIN_EMAIL` and `INITIAL_ADMIN_PASSWORD` to seed your first admin user on boot.

### 4. Install Dependencies

```bash
pnpm install
```

> [!NOTE]
> Zenith strictly enforces `exact` versions and `link-workspace-packages=true`. Do not bypass `pnpm` by using `npm` or `yarn`, as this will destroy the monorepo graph structure.

### 5. Boot the Development Cluster

```bash
pnpm dev
```

This invokes Turborepo to orchestrate parallel builds of `@zenith-open/zenithcms-core` (Backend) and `@zenith-open/zenithcms-admin` (Frontend SPA).

### Expected Output

```text
╔════════════════════════════════════════════════╗
║       Zenith CMS — Online                      ║
╠════════════════════════════════════════════════╣
║  REST API   →  http://localhost:3000/api/v1    ║
║  GraphQL    →  http://localhost:3000/graphql   ║
║  Swagger    →  http://localhost:3000/api-docs  ║
║  Admin UI   →  http://localhost:3000/admin     ║
╚════════════════════════════════════════════════╝
```

### 6. First Boot — Admin User Seeding

On your first boot, if the `users` table is empty, navigating to `http://localhost:3000/admin` will redirect you to the **Zenith CMS Setup Wizard**. 

You will use this beautifully designed React UI to securely provision the initial Super Admin account.

## Zenith CLI Reference

After installing `@zenith-open/zenithcms-cli`, the following global commands are available via both `zenith` and `zenithcms`:

```bash
zenith generate-types       # Generate TypeScript interfaces from zenith.config.ts
zenith export-schema        # Export the full collection schema as JSON
zenith export-data          # Export all content data to a JSON archive
zenith migration:generate   # Generate a new database migration
zenith migration:run        # Run all pending migrations
zenith migration:status     # View migration history and pending state
zenith sync:blocks          # Sync local block definitions to the database
zenith create-plugin        # Scaffold a new Zenith plugin package
zenith start                # Start the CMS server
```

### `zenith generate-types`

Reads `zenith.config.ts` (or `cms.config.ts`) from the current working directory and outputs typed TypeScript interfaces for all collections and globals.

```bash
zenith generate-types --output zenith-types.d.ts
```

**Output example:**

```typescript
/**
 * Zenith Auto-Generated TypeScript Definitions
 * Generated via "zenith generate-types"
 * DO NOT MODIFY MANUALLY.
 */

export interface ZenithDocument {
  _id: string;
  createdAt: string;
  updatedAt: string;
  status?: 'draft' | 'published';
}

export interface Posts extends ZenithDocument {
  title: string;
  slug: string;
  description?: string;
  content?: any;
}

export interface ZenithSchema {
  collections: {
    posts: Posts[];
  };
  globals: {};
}
```
